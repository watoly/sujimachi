# sujimachi

**複数の CSV を横断してキーワードを探す、オフラインの Web ツール。**

カラム構成がばらばらな CSV を何十本まとめて放り込んでも、**カラム名に依存せず**キーワードで
検索し、ヒットした行を該当箇所のハイライト付きで一覧表示します。キーワードは自由に定義した
**グループ**（例: 重要 / 注意 / 参考）に分類でき、結果はグループごとに色分けされます。

数万行・数百 MB を目視で追う代わりに、**見るべき行だけを先に浮かび上がらせる**ためのツールです。

## 特徴

- **完全オフライン処理** — 解析はすべてブラウザ内で完結します。読み込んだデータはサーバーにも外部にも一切送信されません。
- **複数 CSV の横断検索** — ファイルを複数選択、または**フォルダごとドロップ**して一括投入。ファイルごとにカラムが違っても、そのまま横断して検索します。
- **カラム名に依存しない** — 既定では全カラムを検索対象にします。結果表示用の日時カラムは、値が日付らしいかを見てファイルごとに自動判定します。必要ならファイル単位で検索対象カラムを絞れます。
- **大きなファイルでも固まらない** — 全行をメモリに載せず逐次読み取ります。実測で **825 MB / 550 万行を約 32 秒**、ピークメモリ 240 MB 程度。進捗表示と中断ができます。
- **3 つの一致方式** — 部分一致 / 単語単位 / 正規表現をキーワードごとに選べます。
- **グループは自由に定義** — 数も名前も色も変更できます。1 行が複数グループに該当する場合はすべてのバッジを表示します。
- **キーワードのテキスト入出力** — 1 行 1 キーワードの `.txt` を、グループごと／全グループまとめて読み込み・書き出しできます。
- **絞り込み・書き出し** — グループ・ファイル・フリーワードで結果を絞り込み、該当行を CSV で書き出せます（Excel 用に BOM 付き UTF-8）。

## 必要環境

- Node.js 20 以上（開発時。配布版の利用には不要）
- モダンブラウザ（Chrome / Edge / Firefox など）。フォルダのドロップ／選択は Chromium 系が確実です

## セットアップと起動

```bash
npm install
npm run dev        # http://localhost:5173
```

本番ビルド:

```bash
npm run build      # dist/ に静的ファイルを生成
npm run preview    # ビルド結果をローカル配信して確認
```

### 配布用ビルド（単一 HTML）

Node.js も静的サーバーも用意できない環境向けに、JS/CSS をすべて 1 枚の HTML へ
埋め込んだ配布版を作れます。

```bash
npm run build:standalone   # dist-standalone/sujimachi.html （約 210 KB）
```

出力された `sujimachi.html` は**ブラウザで直接開くだけ**（`file://`）で動作します。
サーバー・インストール・ネットワーク接続はいずれも不要です。

> ES モジュールは `file://` から読み込めないため、このビルドは出力形式を `iife`
> （クラシックスクリプト）にしたうえでインライン化し、`#root` 生成後に実行されるよう
> `</body>` 直前へ差し込んでいます。詳細は `scripts/build-standalone.mjs` を参照。

## 使い方

### 解析画面

1. **CSV を読み込む** — フォルダをドロップするか、「ファイルを選択」「フォルダを選択」から投入します（`.csv` 以外はスキップ）。後から追加投入もできます。
2. **（必要なら）ファイルごとの設定** — ファイル名をクリックすると、検索対象カラムと日時カラムを変更できます。既定は「全カラム検索・日時は自動判定」です。
3. **キーワードの有効／無効** — グループごとにまとめてオン／オフできます。
4. **「解析実行」** — マッチした行が、ファイル名・日時・グループバッジ付きで一覧表示されます。行をクリックすると全カラムを展開表示します。
5. **絞り込み・書き出し** — グループタイル、ファイル選択、フリーワードで絞り込み、必要なら CSV で書き出します。

### キーワード設定画面

ヘッダーの「キーワード設定」タブで開きます。

- **グループの管理** — 追加、名前の変更（クリックして編集）、色の変更、削除
- キーワードの追加・削除、ON/OFF、クリックで一致方式を切り替え
- **テキストから読み込み** — 1 行 1 キーワードのリストを貼り付けるか `.txt` を選び、「追加」または「このグループを置き換え」
- **まとめて書き出し／読み込み** — 全グループを 1 つの `.txt` で入出力

## キーワードのテキスト形式

```
## キーワードセット
## 書式: 1行1キーワード / 「# グループ名」でグループを切替

# 重要
ERROR
返品
#- 保留

# 注意
timeout
"LINE"

# 参考
"SD"
/^5[0-9]{2}$/
```

正規表現はセルの値ごとに評価されるため `^` と `$` が使えます。
上の例は値がちょうど 3 桁の 5xx であるセルだけに一致します。

| 記法 | 意味 |
| --- | --- |
| `キーワード` | 部分一致（既定では大文字小文字を区別しない） |
| `"キーワード"` | 単語単位で一致（後述） |
| `/…/` | 正規表現として扱う |
| `# グループ名` | 以降の行のグループを切り替える見出し。存在しない名前なら新しくグループを作る |
| `#- キーワード` | 無効化された状態で読み込む（書き出し時にも使用） |
| `##` で始まる行 | コメント |

グループごとの読み込み欄では見出しは不要です。リストをそのまま貼り付けてください。

### 単語単位の一致について

短い英字語は部分一致だと誤検知を量産します。`LINE` は `online` / `deadline` / `pipeline` に、
`Box` は `Mailbox` / `Dropbox` / `sandbox` に当たってしまいます。
`"LINE"` のように囲むと単語単位でのみ一致します。

境界の判定は **キーワードのその側の端が ASCII 英数字のときだけ** 隣接文字を検査します。

| キーワード | 一致する | 一致しない |
| --- | --- | --- |
| `"SD"` | `Generic SD Card`、`SD_CARD` | `SDELETE64.EXE` |
| `"1102"` | `error 1102` | `2811020` |
| `".xlsx"` | `report_2025.xlsx` | `report.xlsxbak` |
| `"顧客"` | `顧客名簿.xlsx` | — |

日本語には語の区切りが無いため、単純な `\b` 相当を全語に適用すると `顧客` が `顧客名簿` に
一致しなくなり実用になりません。上記の規則により、日本語の語は単語単位を指定しても
挙動が変わりません。

## サンプル

`samples/` に動作確認用の**架空データ**を同梱しています。カラム構成はすべて異なります。

| ファイル | 内容 |
| --- | --- |
| `orders.csv` | 受注データ |
| `support_tickets.csv` | 問い合わせ履歴 |
| `access_log.csv` | アクセスログ |
| `keywords_example.txt` | キーワードテキスト形式の例 |

3 つの CSV をまとめて投入し、`keywords_example.txt` を「まとめて読み込み」すると、
横断検索・グループ別の色分け・日時カラムの自動判定を確認できます。

## 大きなデータを扱うとき

数百 MB のファイルでもそのまま投入できます。全行をメモリに載せず逐次読み取るためです。

実測（164 ファイル / 825 MB / 550 万行、Chromium）:

| 項目 | 結果 |
| --- | --- |
| 読み込み | 約 4 秒（この時点ではヘッダーのみ読む） |
| 全量走査 | 約 32 秒（約 21 MB/秒） |
| ピークメモリ | 約 240 MB |

- 解析中は進捗バーが出ます。画面は固まりません。「中断」でいつでも止められます。
- 結果が表示上限（既定 5 万件）を超えても、**走査は必ず全ファイル最後まで行われます**。上限を超えた分が表示されないだけで、見ていない領域はできません。
- 絞り込みには結果上部の**キーワード別ヒット件数**を使ってください。件数を稼いでいる語をその場で無効化できます。

## 設計メモ

- フロントエンドのみ（React + TypeScript + Vite）。バックエンドは持ちません。
- CSV パースは [PapaParse](https://www.papaparse.com/)。値はすべて文字列として保持し、原文を変えません。
- 多パターン検索は Aho-Corasick（`src/lib/ahocorasick.ts`）。走査回数がセル長にのみ比例するため、キーワードを増やしても速度がほぼ変わりません（素朴な実装比で約 6.9 倍）。
- 大きなファイルは `Papa.parse` の `chunk` で逐次処理し、マッチした行だけを保持します（`src/lib/analyze.ts`）。
- V8 のスライス文字列対策として、保持する文字列は親チャンクから切り離しています。理由は `src/lib/strings.ts` に詳述。
- 実データを誤ってコミットしないよう、`.gitignore` で `/data` を無視しています。
